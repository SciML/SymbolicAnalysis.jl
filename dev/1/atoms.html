Atoms for DCP and DGCP ​

This page is intended to be a reference for the atoms that are currently implemented in this package with their respective properties. As much as possible atoms are created with functions from base, standard libraries and popular packages, but we also inherit a few functions from the CVX family of packages such as quad_form, quad_over_lin etc. and also introduce some new functions in this package. Description of all such special functions implemented in this package is available in the Special functions section of the documentation.

Norm ​

norm(x, p) is a norm, hence convex, only for p ≥ 1. For 0 < p < 1, (Σ|xᵢ|ᵖ)^(1/p) is concave on the nonnegative orthant and indefinite elsewhere, so the concave certificate requires an argument whose propagated sign is Positive (e.g. norm(sqrt.(u), 0.5)). A symbolic p or p ≤ 0 gets no curvature.

Perspective ​

perspective(f, x, s) = s*f(x/s) for s > 0 inherits the sign and curvature of f when that positivity is established (a positive constant, or a variable with a positive VarDomain / propagated sign) and f has a DCP rule. Monotonicity in x matches f's; the s slot is AnyMono and accepts only affine s for a joint certificate. If f has no rule or s > 0 cannot be proved, the certificate is UnknownCurvature / AnySign.

perspective(f, x, s)otherwiseAnySignUnknownCurvatureAnyMono

Inverse ​

inv(x) = 1/x is convex-decreasing and positive only on (0, ∞). The atom exists for every nonzero x and is concave on the negative reals, so the certificate requires a known-positive argument (same house rule as / and xexpx). Matrix inv keeps the Loewner-order semidefinite rule.

invprod(x) = 1/∏xᵢ is convex-decreasing on the positive orthant only; a mixed-sign product lands in the concave branch of 1/t, so the argument must be known positive.

Bilinear atoms ​

dot, conv, kron, dotsort, quad_form and huber's threshold slot are bilinear: each is a convex (or affine) atom only when the argument it is linear in is a constant. With every argument symbolic the expression is indefinite, so the curvature depends on the arguments and there is no single table entry.

quad_form is linear in P, so a non-constant P makes x'Px indefinite; a constant but indefinite P does too (quad_form(x, [1 0; 0 -1]) is x[1]^2 - x[2]^2). isposdef matches the semidefinite_domain() the rule declares, so a singular positive semidefinite P gets no certificate. The x slot is increasing_if_positive only for an entrywise nonnegative P: with P = [1 -0.9; -0.9 1], x'Px decreases in x[1] near x = [0.5, 1].

The constant side of dot, conv and kron holds the coefficients of the linear map, which may have either sign, so the affine case is AnyMono.

These signs and curvatures hold at a point of the manifold, so they apply only when the atom's matrix argument provably is one: the variable X itself, or X passed through inv, adjoint, transpose, a positive scalar multiple, or conjugation by a constant nonsingular matrix. The sign rule also accepts sums of such points and constant positive semidefinite matrices (X + γI). Any other argument, such as X .- 5, -X or X - 5I, falls back to the Euclidean rule, so tr(X .- 5) has no sign. For tr, sum and diag, geodesic convexity also survives adding any constant to the point. For eigmax and eigsummax the constant must be symmetric (a symmetric matrix, or a scalar via .- / .+), so eigmax(X .- 5) is GConvex but eigmax(X + [0 3; 0 0]) is not. These mathematical preservation properties are subject to the analyzer's recognition of the symbolic operation. In particular, sum(X) and sum(X .- 5) can return AnySign and GUnknownCurvature rather than receiving the certificates in the table.

Manifold variable and fixed parameters ​

Geodesic curvature is reported with respect to the manifold variable: the symbolic arguments that are points of M, an n×n matrix on SymmetricPositiveDefinite(n) or a vector on Lorentz. Every other free symbol is a parameter held fixed. For example, with @variables y[1:2] X[1:2, 1:2], log_quad_form(y, X) is GConvex on SymmetricPositiveDefinite(2) because X↦log⁡(y⊤Xy) is geodesically convex for each fixed y. A parameter's known size must match its role (y needs length 2 here). Known argument ranks and dimensions are checked for quad_form, log_quad_form, lorentz_homogeneous_quadratic, lorentz_homogeneous_diagonal, lorentz_nonhomogeneous_quadratic, and lorentz_least_squares. For other atoms, including sdivergence and conjugation, callers must ensure compatible argument sizes; a certificate does not establish that the expression can be evaluated. An argument built from the point, such as [sin(X[1, 1]), 0], is not a parameter.

This is not joint convexity in the point and the parameters. A certificate also does not transfer to the expression obtained by substituting something for a parameter; analyze that expression again.
